TLS certificates for Windows servers, issued, renewed and deployed for you.

CertMaster gets certificates from Let's Encrypt or any other ACME authority, binds them to IIS, pushes them to the other services that need them, and renews them before they expire. A web-based Management Hub runs the same work across all of your servers from one place.

Two pieces that work alone or together

CertMaster

Windows service + desktop app, installed on each server

  • Does the ACME work: orders, validation, issuance, revocation.
  • Renews on schedule in the background, with no one signed in.
  • Applies certificates to IIS and runs your deployment tasks.
  • Desktop app (WPF) for creating, testing and previewing requests, with live progress and per-certificate logs.
  • Local REST API and live status feed on 127.0.0.1:9696, protected by a local API key.

CertMaster Management Hub

Windows service + web UI, installed once

  • One dashboard and editor for the certificates on every server.
  • Agents connect out to the Hub, so managed servers need no inbound firewall rule.
  • Users with Administrator, CertificateManager and Viewer roles.
  • The Hub never stores provider secrets: they stay encrypted on each agent.
  • OpenAPI reference at /docs.

Certificates

Everything RFC 8555 offers, with sensible defaults and a full plan of what will happen before it happens.

Any ACME authority

Let's Encrypt, ZeroSSL, Google Trust Services, SSL.com, Sectigo and Actalis are built in. Add custom or internal CAs such as step-ca. External Account Binding (EAB) is supported.

Every certificate shape

Multi-domain (SAN), wildcard and IP-address certificates. RSA 2048, 3072 and 4096 or ECDSA P-256 and P-384 keys, with optional private-key reuse.

Modern ACME options

Preferred chain selection, ACME profiles such as shortlived, and ARI (RFC 9773) replacement orders so the CA can tell you when to renew.

Automatic renewal

Renew a set number of days before expiry, or at one third of the lifetime for short-lived certificates. Failures retry with exponential back-off.

Test and Preview

Test runs dry checks of validation and deployment. Preview shows the full plan: domains, challenges, bindings to add or change, and the tasks that will run.

Revoke and export

Revoke a certificate with the CA, export it as PFX or PEM, and read the request log for every certificate.

Domain validation

http-01

  • A built-in http.sys listener that shares port 80 with IIS, so nothing extra needs to open.
  • Or write challenge files to a web root you choose.

dns-01

  • Native integrations with the providers listed below.
  • About 95 more through the bundled Posh-ACME plugins.
  • acme-dns, or your own scripts.
  • CNAME delegation rules, and propagation checks against the zone's authoritative nameservers before the CA is asked to validate.

    Deployment

    Bind the new certificate to IIS automatically, then hand it to everything else that needs it.

    IIS, automatically

    • Modes: Auto, Single Site, All Sites, Certificate Store Only, or No Deployment.
    • Add or update https bindings, or update existing bindings only.
    • Match existing bindings by hostname, by blank hostname, or by previous certificate.
    • SNI bindings or specific IP and port.

    Deployment tasks

    • Triggers: on success, on error, always, or manual.
    • Retries and run-if-previous-failed options.
    • Targets: the local machine, a Windows network share (UNC), or a remote host over SSH/SFTP.
    • Placeholders such as {PrimaryDomain}, {Thumbprint} and {CertificatePath} in arguments.

    Management Hub

    A browser UI for every server you manage. Agents dial out to the Hub over SignalR; the Hub sends commands and receives progress and summaries back.

    Dashboard

    Every instance and certificate at a glance: what expires within 14 days, which renewals failed and why, and what renews next.

    Certificates

    Browse, create, edit, test, request and renew certificates on any connected server: domains, keys, authorization, IIS deployment and tasks.

    Instances

    Create expiring, revocable joining keys. Join a server from its CertMaster settings in a few clicks.

    Accounts and credentials

    Manage ACME accounts and stored provider credentials on each agent. Secrets are write-only and never returned.

    Users and roles

    Administrator, CertificateManager and Viewer. PBKDF2 password hashes, JWT with rotating refresh tokens, and sign-in rate limits.

    API

    Everything in the UI is in the REST API, documented with OpenAPI at /docs.

    Operations and security

    Encrypted credentials

    Stored credentials are encrypted with Windows DPAPI and never returned by the API or shown in a UI.

    Locked-down data

    The data folder is restricted to SYSTEM and Administrators.

    Self-healing

    Daily database backups, an integrity check at startup, crash-safe settings files and service crash recovery.

    Runs unattended

    Windows services start at boot with no one signed in. A tray monitor shows status at a glance and notifies you when a renewal fails or a service stops.

    Safe edits

    Certificates with a request in progress are protected from conflicting edits, and task problems show as warnings before you run.

    Clear errors

    Missing ACME accounts and wrapped CA failures are reported in plain language, with the underlying ACME problem kept in the log.

    Tested

    Hundreds of unit tests run in CI on every change, plus end-to-end issuance against Pebble, Let's Encrypt's test CA.

    Install

    Installers

    InstallerInstalls
    certmaster-windows-x64-<version>.exeThe CertMaster Agent service, plus the desktop app and tray monitor (optional). The desktop app runs as Administrator.
    certmaster-hub-windows-x64-<version>.exeThe Management Hub service. Setup asks for the port (default 9697) and can open the firewall.

    Both are self-contained and support Windows 10 / Server 2019 or later. Uninstalling asks before removing data.

    First steps

    1. Open CertMaster. In Settings › Certificate Authorities, register an ACME account.
    2. Click New Certificate. Pick an IIS site or type domains, choose how they are validated (Authorization), review Deployment and Tasks, then click Test and Request Certificate.
    3. Optional: open the Hub, sign in as admin with the password from C:\ProgramData\CertMasterHub\initial-admin-password.txt, and change it. Create a joining key under Instances, then join from each server's Settings › Management Hub.

    Put production Hub deployments behind HTTPS (a reverse proxy or Kestrel certificate configuration).

    Build from source

    dotnet build CertMaster.sln
dotnet test CertMaster.sln
./build/publish.ps1    # tests, self-contained publish to ./dist, then both installers

    Needs the .NET 10 SDK on Windows, and Inno Setup 6 for the installers.
